## Anomalies and deviations

- No matrix run failed, timed out, used fallback triage, or returned an unexpected MITRE label.
  Severity was consistently high, matching the earlier pilot; severity has no independent ground-truth score here.
- All five runs logged a MongoDB vector-search warning and used the built-in cosine-search fallback.
  This is a retrieval-backend fallback; model triage succeeded in every run.
- All five Boss proposals recommend Kubernetes NetworkPolicy creation or enforcement; run 1 also suggests pod isolation.
  The deployed [AI4SOAR stub](../../../../scripts/e2e-kind/stub/stub.py) instead blocks sources through
  CI-SIM's `/admin/block` endpoint. The suggested policy mechanism is therefore unsupported by this test deployment.
- Run 3 returned seven lines despite the six-line request. Runs 1 and 4 explicitly require human approval;
  the remaining outputs use proposal wording and do not claim the proposed actions were executed.
- No benign incident occurred, so there is no false-positive rule or source to list.
- An initial smoke invocation exited before deployment with
  `Error: demo scenario not found — set SCENARIO_ID` because I omitted the environment variable.
  Setting the documented scenario ID resolved this setup error; no experiment run was lost.
- HTTP-SIM retained its private-registry catalog image. It is unused by this demo topology;
  the deployed MAG, CI-SIM, and AI4SOAR used the prescribed stub image, and SECANOD used the real probe image.

## Interpretation limits

- MAG is a stand-in generating HTTP-flood traffic; the real MMT probe raises rule 56.
  These results do not evaluate real MAG ICMP or ping-of-death profiles or the optional company-network variant.
- Benign mode observes an idle deployment with kubelet probes, not representative legitimate user traffic.
  Zero incidents in 900 seconds is an observed count, not proof of a zero operational false-positive rate.
- Incidents are held in memory; stopping or restarting the server loses that live state.
  The JSON artifacts and incident audit preserve this experiment's recorded results.
- The rule's MITRE reference is supplied in the triage prompt. Agreement measures adherence to that reference,
  not independent discovery of the attack technique. Severity is reported without an independent labeled baseline.
- MTTD starts immediately before the attack API request and includes request overhead and log-polling delay.
  Latencies come from this local deployment and a small sample; no cold-start/warm-start comparison was controlled.
- The Monitor/Boss path generates recommendations for human review. This experiment does not validate execution
  of those recommendations; the demo has its own preconfigured AI4SOAR reaction.
